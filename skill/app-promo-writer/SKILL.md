# 앱 홍보글 쓰기

앱 자료 3개를 읽고 밖에 내보낼 글 세 가지의 초안을 쓴다. 게시와 등록은 하지 않는다.

## 시작하기 전에 — 자료 찾기

지금 폴더에 `자료/` 가 있는지 본다.

- `자료/앱소개.md` · `자료/업데이트내역.md` · `자료/말투.md` 가 있으면 그것을 쓴다.
- 없으면 만들지 말지 먼저 묻는다. 만들기로 하면 아래를 하나씩 물어 `자료/` 에 세 파일로 저장하고, 저장한 내용을 보여 준 뒤 이어 간다.
  - `앱소개.md` : 앱이 하는 일 한 줄 · 쓰는 사람과 겪는 불편 · 기능 · 가격 · 올라가 있는 스토어
  - `업데이트내역.md` : 버전별로 바뀐 것. 맨 위가 가장 최근 버전이고, 버전 옆 날짜는 스토어에 나온 날이다.
  - `말투.md` : 글의 말투 · 꼭 쓰는 표현 · 쓰면 안 되는 표현 · 이모지 개수 · 꼭 넣을 해시태그
- 사용자가 대답하지 않은 항목은 지어내지 않고 「확인 필요」로 적어 둔다.
- 파일 이름이 「여기에_」로 시작하는 안내 파일은 자료가 아니므로 건너뛴다.

사용자가 세 가지 글 가운데 일부만 부탁하면(예: 업데이트 공지만) 2단계에서 그 글만 만든다. 1단계와 3단계는 그대로 한다.

## 흐름 3단계

만든 파일은 모두 지금 폴더의 `결과/` 에 새 파일로 저장한다(없으면 만든다). 파일 이름 끝에 날짜(YYMMDD)를 붙이고, 같은 날 다시 만들면 `_2` 를 붙인다.

### 1. 읽기
자료 3개를 읽고 글에 쓸 재료를 뽑아 `결과/홍보재료_날짜.md` 로 저장한다.

1. 앱 한 줄 소개
2. 쓰는 사람과 그 사람이 겪는 불편
3. 내세울 기능 3~5개 — 기능마다 어느 파일의 어느 항목에서 왔는지
4. 가장 최근 버전에서 바뀐 것
5. 가격 · 스토어
6. `말투.md` 에서 지킬 것

이 여섯 가지 가운데 자료에 없는 항목만 「확인 필요」라고 쓴다. 그 밖에 게시할 때 필요해 보이는 것(스토어 링크 등)은 3단계 확인표의 「내가 정할 것」에 적는다.

### 2. 만들기
아래 글을 각각 새 파일로 만든다. 한도가 있는 항목마다 글자 수를 실제로 세어 옆에 적는다(공백과 줄바꿈 포함, 눈대중 금지).

| 파일 | 담을 것 | 한도 |
|---|---|---|
| `결과/스토어설명문_날짜.md` | App Store 부제 | 30자 |
| | App Store 프로모션 텍스트 | 170자 |
| | 설명문 본문 — 첫 세 줄에 앱이 하는 일이 다 보이게 | 4,000자 |
| | App Store 키워드 — 쉼표로 이어서 | 100자 |
| | Google Play 간단한 설명 | 80자 |
| `결과/인스타글_날짜.md` | 서로 다른 각도의 글 3안(예: 겪는 불편 · 쓰는 장면 · 이번에 바뀐 것). 안마다 첫 줄 한 문장, 본문, 해시태그 5~10개, 같이 올리면 좋을 사진이나 화면 한 줄 | 한 안에 2,200자 |
| `결과/업데이트공지_날짜.md` | 가장 최근 버전 하나에 대한 스토어 「새로운 기능」 문구 | 500자 |
| | 앱 안 공지문 — 제목 한 줄 + 본문 | 없음 |

업데이트 공지에는 `업데이트내역.md` 에 적힌 변경만 쓴다.

**여기서 멈춘다.** 만든 글의 목록과 글자 수, 「확인 필요」 개수를 보여 주고 「이대로 3단계로 갈까요?」라고 묻는다. 사용자가 답하기 전에는 다음으로 가지 않는다.

### 3. 나가기
`결과/게시전_확인표_날짜.md` 를 만든다. 글마다 아래 네 가지를 적는다. 앞의 둘은 표로 만든다.

1. 글자 수 — 한도 / 실제 / 통과 여부
2. 숫자 · 가격 · 버전 · 날짜 대조 — 자료에 적힌 값 / 글에 쓴 값 / 같은지
3. 「확인 필요」로 남긴 곳
4. 게시하기 전에 내가 정할 것 — 올릴 사진, 게시 날짜, 스토어 링크 등

**여기서 멈춘다.** 만든 파일 이름과, 게시하기 전에 확인할 곳이 몇 개인지 한 줄로 말해 준다.

폴더에 `작업일지.md` 가 있으면 맨 아래에 한 줄 적는다: `날짜(YYYY-MM-DD) · 한 일 · 만든 파일 이름`

## 규칙

1. 자료에 없는 것은 지어내지 않는다. 내려받은 수 · 별점 · 순위 · 수상 · 사용자 후기 · 언론 보도는 자료에 적혀 있을 때만 쓴다. 모르면 「확인 필요」라고 쓴다.
2. 「1위」 「최고」 「유일」 「완벽」처럼 견줄 근거가 필요한 말은 쓰지 않는다. 다른 앱을 깎아내리지 않는다.
3. 가격 · 버전 · 날짜 · 기능 이름은 자료에 적힌 그대로 옮긴다. 아직 나오지 않은 기능을 나온 것처럼 쓰지 않는다.
4. 밖에 내보낼 글(스토어 설명문 · 인스타 글 · 업데이트 공지)의 말투와 이모지는 `말투.md` 를 따른다. 쓰지 말라고 적힌 표현은 쓰지 않는다. 홍보재료와 확인표는 정리 파일이라 말투를 맞추지 않아도 된다.
5. 이모지 개수에서 「글 하나」는 인스타 한 안, 스토어 설명문 전체, 업데이트 공지 전체를 각각 하나로 센다. 키워드와 소제목처럼 문장이 아닌 것에는 말투를 적용하지 않는다.
6. 사람 이름 · 연락처는 쓰지 않는다.
7. 초안까지만 만든다. 스토어 등록 · 인스타 게시 · 공지 발송은 사용자가 한다.
8. `자료/` 의 원본은 고치지 않는다(처음에 사용자와 같이 만드는 경우는 예외).

글자 수 한도는 스토어 정책이 바뀌면 달라질 수 있다. 확인표 끝에 「등록하기 전에 스토어 화면에서 한도를 확인하세요」라고 한 줄 적는다.
